# Grand Theft Auto III – The Definitive Edition (`0100C3C012718000`)

Update 1.0.8 (v524288), SDK 10.4.1. Rockstar's RenderWare game on Unreal Engine 4 (the `rhi.` console-variable generation, names stored UTF-16), NVN, `main` / `subsdk0` (the SDK's movie library) and `sdk` (`main` = `bb2dda80e83d0b2f311929793f0613c8`, `sdk` = `d9add76fc264863d85fbbd1d70076c76`, `subsdk0` = `84e50460493a12f26100e5150fbff271` — the build FPSLocker's 60 fps patch is for). The shaders are inline in the paks (the cooked packages and the engine's global shader cache), so the split reads them from there and not from a shader code archive.

Status: on the Mac (2026-11-13/14, M1 Max, macOS 27.2), from a fresh install: the first-run terms screen, the copyright notice, the intro's unfolding newspaper, the main menu, the opening mission scene, the bank cutscene ("you're just small time") and free roam on Callahan Bridge, walking, the camera and a punch — 60 fps, frame time p50 16.70–17.27 ms, 0 `[RED]` lines. 120 fps is selectable and off by default; its mechanism is proven, a sustained 120.0 mean is not (see [Frame rate](#frame-rate)). No IPA has been built and iOS is untested.

## What it needs

| Setting | Where | Why |
|---|---|---|
| `fps_target 60`, `ue_fps_cvar t.MaxFPS`, `ue_fps_off on` | [`game.tsv`](game.tsv) | the engine's own frame limit, found by name: `t.MaxFPS` is written 0 and the host's present cap paces the frames ([Frame rate](#frame-rate)) |
| `fps_max 120` | `game.tsv` | unlocks the launcher's **Frame rate** row and `DM_FPS_TARGET=120`; the default stays 60 |
| `depth_mode zero` | `game.tsv` | the game calls `nvnDeviceSetDepthMode` with near = 0 in its check boot, so the pipeline bases made before it runs are made for that mode |
| `mem_reserve 0x1028000000`, `mem_alias 0x1000000000`, `mem_stack 0x10000000`, `app_pool 0xCD500000` | `game.tsv` | Unreal's 62 GB address region: the rewriter cuts `FMallocBinned3`'s constructor in any Unreal 4 / 5 main (`dm/tools/ue_malloc.py`) and gives that region what the alias region has room for (`dm/tools/ue_region.py`). After the cut the regions reach alias +62.06 GB within the 64 GB alias region in the first 15 s in `nnMain`, and the heap check measures 0.01 GB |
| `sys_resource 0x5000000` | `game.tsv` | the NPDM declares 80 MB of system resource |
| `shader_groups ShaderArchive-Global-=global ShaderArchive-=game`, `shader_note` | `game.tsv` | the split needs the group rule key; no pak entry here names a shader code archive, so every row lands in its `other` group |

No host rule is specific to this game: the two mechanisms it needed (`FPS_UNLIM` and the display switch, four host files) are general and documented in [Found on this game](#found-on-this-game).

## Frame rate

**60 fps.** `t.MaxFPS` was located by the rewriter's name search, with no address in the profile: `main.fixups.tsv` has `UE_CVAR:t.MaxFPS 0x7584630`, which is FPSLocker's `t.MaxFPS` object for this build (`0x7584640`) minus its `+0x10` value pointer, plus `UE_CVAR:rhi.SyncInterval 0x7455a40`. `nvn.SyncInterval` is absent (this is the `rhi.` generation), and `strings` counts 0 for all of them because UE 4.26/4.27 stores the names UTF-16. `hle_fpslock.c` writes the game thread's and the render thread's copies every frame they differ, and `rhi.SyncInterval` 2 → 1 vsync.

- **The engine's limit is written 0, not 60.** This build's limiter sleeps a whole frame period (1 / MaxFPS) and subtracts none of the frame's work, so a value at the target lands after the host's 60 Hz present tick every frame, the pacer keeps its phase and gives each frame two ticks. Measured in one run (`shots/run12.log`, one launch, `DM_CTL cvarf`, 16 s a step, p50 frame time): `t.MaxFPS` 60 → 33.45 ms (30.0 fps), 61 → 21.0, 120 → 22.6–25.4, 240 → 17.0, 0 → 16.48 (60.7 fps). So the host writes 0 and its present cap at 60 paces the frames, and the game steps by the time that really passed: 60 fps is the same game speed as 30 (FPSLocker's patch for this build raises the same cap).
- **60 measured from the packaged bundle** (`shots/b60_final.log`, headless, same route): 24 windows 59.8 / 59.9 / 60.0 / 60.1 / 60.2 fps (two 55–57 windows on launch hitches), frame time p50 16.72–16.80 ms, GPU p50 0.41 ms, submit 0.17 ms, 0 `[RED]`, 0 shader misses. `shots/run14.log` (one launch, 3,300 frames) is the same rate with p95 34.2–44.9 ms under other jobs' load.

**120 fps.** `fps_max 120` only unlocks the rung; `fps_high()` (`hle_nvn.c`) refuses 120 without an engine limiter the host writes, and this title has one and no frame step page, so the gate passes: `[nvn] 120 fps: cap 0 → 120 fps`, `present tick 120 Hz`, `t.MaxFPS 30 → 0 (no engine limit; the present cap paces at 120)`.

- **A 144 Hz link cannot pace a 1/120 s tick.** The Mac drives the ASUS P275MV PLUS at 3840x2160 on a 144 Hz link, and 144 / 120 = 1.2 refreshes a tick, so presents alternate 6.94 and 13.89 ms. The panel has a 120 Hz mode of the same size (`CGDisplayCopyAllDisplayModes`: iomode 104, 1920x1080 pts / 3840x2160 px at 120.000 Hz, against the current 144.000), so the host switches to it while the 120 rung runs and restores the previous mode on quit, on SIGTERM/SIGINT and when the rung leaves 120 ([Fullscreen switches the screen to a rate the frame rate divides](../../../docs/reference/frame-rate.md#fullscreen-switches-the-screen-to-a-rate-the-frame-rate-divides)). Proved without the game by a harness beside the build (`dm_mode_switch 120 2`): switch OK (0), `NSScreen.maximumFramesPerSecond` 144 → 120, four samples at 120.0000 Hz while holding, restore OK (0), 144 Hz after, `restored to the previous mode: YES`.
- **The screen's own mode is back every time the host exits.** Both 120 runs logged `front end: the host is exiting: the screen gets its own mode back` → `front end: screen back at 144 Hz` → `graceful exit done (0.404–0.410 s)`, and the harness reads iomode 100 / 144.000 Hz afterwards. A 60 launch never touches the display: `shots/b60_lk120b.log` has no switch line at all, 144 Hz before, at SIGTERM and after.
- **What it delivers** (`shots/b120_lk120b.log`, packaged bundle, windowed, display at 120 Hz, 130 s): 23 windows **mean 90.0 fps** (median 91.0, best 117.2, worst 60.0), frame time p50 7.14–16.60 ms (median 9.55), submit p50 0.30 ms, GPU p50 0.41 ms, 0 `[RED]`. `shots/b120_lk120.log` (same route, display held awake less often): 16 windows mean 76.9 fps, p50 median 8.96 ms.
- **Honest reading: the pacer and the renderer hold 120, the delivered mean on this Mac tonight did not.** The renderer needs 0.41 ms GPU + 0.11 ms submit of the 8.33 ms a tick gives (16× headroom), so this is not a cost ceiling: every miss is a whole frame of 22–45 ms with GPU and submit under 2 ms in it — 1,915 of 1,924 `[longframe]` lines in one run, median whole frame 31.9 ms — the guest frame thread off-CPU. The box carried another session's Borderlands dev host, a Batman Arkham City launcher and Spotlight (load 2.3–4.8), and the windowed runs were taken with the session locked (the game window behind the login window), where the display link stalled about 12 times in 130 s.

## Files and shaders

- **6,179 shader keys**, from the split's own pass over the two paks: 3,886 pixel, 1,464 vertex, 803 compute, 26 geometry. All of them are inline in `pakchunk0-Switch.pak`, in the two forms Unreal keeps shaders in without a shader code archive: 4,399 in the cooked packages (`#<package>.uexp#UE<offset>` in the source column) and 1,780 in the engine's global shader cache (`#Engine/GlobalShaderCache-GLSL_SWITCH.bin`). All translate (`6,179 of 6,179 shaders ready` for the Mac). `shader_facts.tsv` holds the 803 compute answers, `shader_pairs.tsv` the 1,464 vertex / pixel pairs (1,464 single-stage programs pair with one cover pixel shader, `6876978c8c1f7ad3`). `pso_pairs.tsv`, `shader_map.tsv.conflicts.tsv` and `pso_manifest.tsv` are the empty forms.
- **The map is the split's output alone, and that is what a build checks.** `scripts/build_ipa_from_nsp.py` compares a registered profile's tables with the split's output row for row and stops on any difference, so the committed `shader_map.tsv` is exactly what `shader_split.py` writes from these game files with this `game.tsv` (diffed byte for byte, 6,179 rows). A row a run-time capture produced is game bytes and cannot be committed without breaking every other build.
- **37 keys are not committed.** They came from run-time captures: 21 on the boot / intro route (`DM_NVN_SHDUMP`, `shots/run7.log`, the 23 keys that route missed) and 16 from the night sweeps (9 + 7: `capture_sweep/`, `capture_sweep3/`). They were folded into `ps_capture.bin` / `vs_capture.bin` packages as `capture#RAW` map rows by a script kept beside the build (`fold_capture.py`, in the porting notes, not in this repository), which is the 6,216-row map the app was packed with. **They are not in this profile**: a build from it has 6,179 keys, and the bank cutscene's 7 (5 ps + 2 vs) are among them, so that scene logs `shader <key> is not in the shader map` and `program has no vertex shader (or it is not mapped)` and its characters do not draw until those keys are captured again and folded.
- **Coverage is partial, and the reason is a reader limit.** The split reports `15,651 file(s) could not be read` out of the two paks (`<work>/logs/shader_split.log`: `Engine/Config/BaseCompat.ini block 0 does not decode (the stream does not end within its 0x3800 raw bytes)`), not a translation failure. Routes swept clean (0 misses, 0 `[RED]`): the terms screen, the notice, the intro, the main menu, the opening mission scene, the bank cutscene (with the 37 folded keys) and free roam on Callahan Bridge. The rest of the world is not covered.
- 1 shader is not proven bounded (`c1_guard.py`: `c1_full.tsv: not proven bounded: 1 shaders`), and 7 bindless texture accesses are deleted in one translated shader (`1105dc0e4648ddb8`, `[RED] lost without failing`). `c1_full.tsv` and `cb_extent.tsv` are made by a full `dmsh_build.py` run and are not committed.

## Mac routes

- Build with `scripts/build_ipa_from_nsp.py <NSP folder> -k <prod.keys> --platform mac-app --app-name "Grand Theft Auto III" --work-dir <work> -o "Grand Theft Auto III NX.app"`; the Mac-only stages need `glslangValidator` and `zstd` on the path.
- The bundle's own host, headless, one launch: `DM_WINDOW=0 DM_AUDIO=0 DM_OE_SCRIPT=focus=1@5` and A at 25 s and 60 s to pass the terms and notice screens into the intro (`shots/run14.log`).
- Windowed: the scripts kept beside the build, `run_window.sh` (dev host) and `verify_bundle_window.sh` (the packaged bundle), with `DM_FPS_TARGET=120` for the rung; `DM_PRESENT_HZ=120` names the present rate in a headless run. `caffeinate -u` is needed to wake the panel before a mode change: a sleeping display refuses every mode change with `CGError 1014`.
- The launcher's **Frame rate** row offers 30 / 60 / 120 and starts at 60 (`settings.tsv`'s `120=120 fps?DM_GAME_FPS_MAX==120&platform:mac`, satisfied by `fps_max 120`).

## Open

- **Not played interactively:** no save game, every run `DM_AUDIO=0`, and the windowed runs were behind a locked login window — nobody has watched this on screen as a picture, or heard it.
- **120 fps: the mechanism is proven, a sustained 120.0 mean is not.** p50 8.1–9.6 ms and 0.7 ms of render work in the 8.33 ms tick, but the delivered windows run 63–117 fps (mean 90.0 over 23) because 22–45 ms whole frames arrive with the GPU idle. The rung ships selectable with 60 as the default.
- **The measurement still missing** is a visible-window run on an unlocked Mac, which can only flatter these numbers.
- **Shader coverage of the world:** 15,651 pak entries unread by the split, and the 37 keys that came from run-time captures are not in this profile ([Files and shaders](#files-and-shaders)).
- **The iPhone block is unmeasured:** `mem_alias 0x1000000000` is the provisional 64 GB region, and the packer's heap and region checks only prove the Mac side (heap 0.01 GB, regions reach alias +62.06 GB of 64 GB).
- 1 shader not proven bounded (`c1_full.tsv`, not committed); 7 bindless texture accesses deleted in one translated shader.
- The prewarm list (`pso_manifest.tsv`) is empty; a packed run prewarmed 1,784 shaders / 23 pipelines / 7 compute shaders without a recorded seed list.

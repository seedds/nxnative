# Super Mario Bros. Wonder – Nintendo Switch 2 Edition + Meetup in Bellabel Park

Nintendo Switch 2 Edition, **Program 1** (`040015100B514001`) of the Switch 1 application `010015100B514000`, **v327680**, display version **1.2.1**, SDK **21 (Ounce)**, **NVN2**, Nintendo EPD (sead / agl / gsys). The Bellabel Park add-on content uses DLC `010015100B515001`, update **v131072**. This is a *different* executable and shader set from the original Switch 1 [Wonder](../010015100B514000/README.md); the existing Switch 1 profile and its builds must not be changed.

## What the profile needs

- The Edition executable's Program 1 has `main=ec47e6f8846d2a7b6892e2682845c725`, `subsdk0=3fddebac0ad5c3f9e018dcadca9e55ed` and `sdk=31945f745022d0232d2562252641b3d3`. `modules main subsdk0 sdk` follows its own imports. This profile registers **only** that build. Other Edition builds need a fresh binary survey and new shader facts.
- `mem_reserve 0x278000000`, `mem_alias 0x118000000`, `mem_stack 0x10000000`, `app_pool 0x240000000`, and `sys_resource 0x1000000` reflect the Edition's large memory layout. Its SDK requested a roughly 4.94 GiB heap, and the NPDM declares a 16 MiB system resource. Do not reuse Switch 1's memory partition.
- `render_cond on` is **required**. The Edition uses NVN conditional rendering to suppress a second shadow-mask clear. Without it, the host performs the later zero clear even when the predicate forbids it: the R8 mask subsequently downscales black instead of white, making the fountain and ground incorrectly dark. A/B GPU pass captures found the earliest mismatch in the first shadow-mask producers, and the profile's conditional-render setting restored the Switch 1 reference coloring.
- The current upstream BAHS parser fix (`04df08d4`) excludes three false program entries previously inferred from the `agl` control-section words. The resplit of the same v327680 game files removes these three phantom keys, renumbers subsequent stage indices and preserves both vertex/pixel pair tables; it is **not** a change of game dump.
- `shader_versions v327680`, the 30,630-entry Program 1 shader map, `pso_pairs.tsv` and the game's own shader facts are separate from the Switch 1 title. The build must translate them for the **current** `DMSH_CHAIN`; older experimental Mac shader libraries cannot be reused after a chain update.
- **No NVN scratch workaround is needed in this profile.** Upstream main's general, default-on command recorder (commit [`f02d0474`](https://github.com/seedds/nxnative/commit/f02d0474cf1ed1de32ccee1313e1448d4f7da401)) accounts for END, links and calls in control memory and packs regular commands into real guest-accounted bytes. The former profile key `nvn_draw_ctl on` and independent four-byte-ticket PR #1609 are superseded; the original RESTBL fits without either or a title-specific heap patch. See the [November 10 retest](#november-10-2026-original-restbl-upstream-retest).

## Input and dependencies

The source is an **extracted** update-only folder, `updates/327680/program/0/{exefs,...}` and `updates/327680/program/1/{exefs,romfs,control}`, with Program 1 selected; the new Bellabel DLC lives under `dlc/010015100b515001/0/updates/131072/program/0/romfs`. The original official Edition title and 384-pixel icon are in `program/1/control/Acd_1/`. Do not commit those game files, any decrypted executable, shaders or extracted resources to nxnative.

- **Prerequisite:** upstream [PR #1253](https://github.com/seedds/nxnative/pull/1253), or its equivalent, makes the dump packer understand `program/<n>` and an update-only Edition layout. At the time of testing, #1253 had merge conflicts and one failing lint check; until that work lands, an unmodified upstream builder cannot pack this folder.
- **Prerequisite:** [PR #1586](https://github.com/seedds/nxnative/pull/1586) preserves the selected Edition Program 1's **own Mac save/cache identity** `040015100B514001`, distinct from the original application ID `010015100B514000`. The first clean build pointed its `DMTitleID` and default bundle ID at the original Wonder saves despite selecting the Edition profile. The independent, general packer fix is now upstream for review (40 focused tests passed); it complements pending #1253 without duplicating that PR. Original Switch 1 saves must remain separate.
- SDK 21's movie output calls `GetVirtualOutputDeviceProperties` and an `OpenOutputStream` overload without flags. Separate [PR #1561](https://github.com/seedds/nxnative/pull/1561) supplies the missing general host hooks required for the opening movie.
- [PR #1562](https://github.com/seedds/nxnative/pull/1562) imports the Nintendo Control NCA and `Acd_1` Edition title/icon automatically once Program 1's folder is selected, rather than relying on manual labeling or the Switch 1 icon.
- **BFRES issue resolved in upstream code:** [issue #1580](https://github.com/seedds/nxnative/issues/1580) documents why the Edition's original-RESTBL model heaps overflowed with oversized host command recordings. Upstream main merged general command-memory semantics in `f02d0474`, superseding and closing [#1609](https://github.com/seedds/nxnative/pull/1609). With the actual upstream NVN code and no resource-table override, the November 10 manual retest measured `NpcCommonerA` scratch **`0x4e84` against `0x5000`** and `PlayerPeachElpWM` **`0x3f94` against `0x4000`**; the complete evidence was [reported to the maintainer](https://github.com/seedds/nxnative/issues/1580#issuecomment-6781469395). This is no longer a prerequisite PR or profile switch. Superseded [#1565](https://github.com/seedds/nxnative/pull/1565) and the now-unneeded optional overlay packaging [#1564](https://github.com/seedds/nxnative/pull/1564) were closed; neither was merged as part of the fix.
- **Complementary indexed Program0 RomFS:** SDK 19+ `MountRom(name,index)` requires distinct per-program storage. Contributor [#1639](https://github.com/seedds/nxnative/pull/1639) includes related general support, but its game-specific +16 KiB heap workaround is **excluded**. The [BrentRosen-credited fork-only candidate at `2d7b6a4d`](https://github.com/ishtiaq156/nxnative/tree/integration/program1-indexed-romfs-w10-20261107) implements read-only indexed mounts and explicitly supplied Mac Program0 directory/image sidecars. It fails closed before packing if the original source overlaps the output app, temporary/swap/cache paths, or an output is nested inside a signed source app or directory. The source-alias corrections reject symlinked staging `.app.partial`, symlinked/hardlinked `.key.partial`, and an **output `.app` leaf symlink resolving to another signed app**, any of which could mutate original resources. They still allow symlinked parent volumes and a **source leaf symlink inside a real destination `.app` pointing to an independent external image**: the packer resolves and copies the external image before swapping the output; that temporary source link disappears with the old app, so a stable external source path is preferable for repeat builds. The canonical update-only Edition dump has Program0 NPDM and selected Program1 RomFS **but no separate Program0 RomFS** by design; missing original content fails closed, never silently mapped to Program1 for index0. iOS indexed-sidecar packaging is not implemented.
- **Explicit original-image and integration evidence:** The original-title-checked, complete `DMROMFS1` image from an existing signed original Wonder 1.2.1 Mac app passed **read-only source/index preflight** and can be provided explicitly as `romfs_programs/0.img`; this does **not** establish native hardware content/version parity. The earlier [fork-only combined source `1fc48cdb`](https://github.com/ishtiaq156/nxnative/tree/integration/wonder-final-headless-20261107) passed **399/399 headless checks** and an arm64 host-only build, both numeric exit0. The [validated fork-only packer source at `6079730e`](https://github.com/ishtiaq156/nxnative/tree/integration/wonder-required-ci-hygiene-20261107) includes independent #1675/#1682 CI repairs and #1609's historical test-switch registry correction; the credited source's affected Mac/NSP suite passed **116/116**, including the new symlinked-output negative and symlinked-parent positive regressions. The earlier `003626c1` code head passed **114/114 Mac/NSP and 11/11 documentation checks**. These are historical source/packaging tests, not a claimed current-main merge. The later signed upstream-NVN retest regenerated all 30,630 shaders with chain `bc8830d4ba5a`, rather than reusing the previous `844bf1a5ea8f` library or Metal archive.
- Offline Mac packaging and the resource-size-table issue below are distinct from recognizing the game: signing or successful packing does not establish a fresh save boot.

## Mac bring-up and what was checked

On a **Mac mini M6, macOS 27.0.1**, an earlier *isolated* experimental Edition port (`671c68e1` plus local host/packer modifications, shader chain `adec7d81d970`) displayed the title, reached in-game scenes and passed gameplay tests across several Wonder courses and Bellabel Park; controller and rumble worked. A subsequent metadata-only patch replaced its provisional window title/icon with the official Edition Control data. **These are historical tests of that older experimental host, not tests of this upstream PR branch.**

A fresh new-game save on the *older experimental host* initially crashed while creating several BFRES models: its guest allocator returned a null pool after a model scratch allocation. A local **diagnostic-only** override raised 1,243 non-animation geometry-model sizes by 16 KiB in a runtime resource-size table, without changing the original ROM. Together with host audio hooks and bounded command-memory experiments, this got through Course900 and the online-selection movie and rendered at least 4,200 frames. **That historical override is not the fix and is absent from this profile.** The later per-model allocator analysis traced the real discrepancy to host NVN command-record bytes. Draft #1609 first repaired the measured cases with four-byte command/control tickets and no RESTBL modification; upstream subsequently replaced it with the general `f02d0474` fix.

A **new clean Mac app** was then built from the PR integration (`710d03e5`, shader chain `844bf1a5ea8f`) with all 30,630 verified shaders, official Edition Control metadata and a GPU-specific offline pipeline archive. Its first two manual launches reached the save menu, then crashed after choosing **Continue**: `[RED] BufferInitialize: pool has no storage`, followed by `h_nvnMemoryPoolGetFlags(NULL)` and host exit 139. That older app later passed courses/Bellabel **with the isolated +16 KiB diagnostic overlay**; this cannot validate original-RESTBL allocation.

A **separately signed 1.2.1 four-byte-fix preview** (host `070a30457362`, original RESTBL, no overlay) subsequently reached New Game character confirmation and the previously failing Peach model in a real course. For real World 1 frame **2350**, its NVN capture contained **33 canonical ticket expansions**; **2/2 independent replays exactly matched the presented 3840×2160 image digest**, while **69 of 334,308 post-frame memory blocks differed**. This demonstrated the earlier draft's BFRES correction and one presented-frame replay, **not** full memory-state equivalence, a complete original-RESTBL course clear, Bellabel Park or sustained multi-queue GPU safety. The superseded #1609 added source tests and a *defensive* 32-byte fallback regression; that 32-byte grant is **below the NVN/NVN2 advertised 512-byte minimum** and must not be claimed as hardware-valid. The original signed app and this separate preview are both preserved; neither was rebuilt for documentation changes.

## November 10, 2026: original-RESTBL upstream retest

A new **16.9 GB signed Mac app** using main `2f131edc` (including general NVN fix `f02d0474`) was built with the required *local, uncommitted* Program 1, SDK21 audio, Control and packaging integration. The NVN host sources matched upstream main; this was **not** a pristine/main-only build, since the other Edition prerequisites have not landed. The original RESTBL was unmodified, the old `nvn_draw_ctl` key was absent, no diagnostic overlay was used, and all **30,630/30,630** shaders were freshly built with chain `bc8830d4ba5a`. The app retained a distinct Program 1 save identity and separate, explicitly supplied original Program 0 RomFS image.

The player manually tested **New Game** and **Peach Continue**, each with an isolated save, on a Mac mini M6. Both exited normally (`0`): New Game logged NVN command-memory intervals through frame **11,700** and loaded `NpcCommonerA`; Continue logged intervals through frame **2,700** and loaded `PlayerPeachElpWM`. All **48** aggregate command-memory intervals recorded **zero out-of-memory callbacks and zero host-lent segments**. There were **no `[RED]` messages**, null-pool aborts or the previous BFRES failure; SDK21 `OutputStream` opened and ran. Late intervals reported zero audio underruns; measured frame times were around **35 ms** (nominally near 30 fps). The player reported the gameplay looked good; earlier course and Bellabel playtesting was also reported, though these two logs do **not** independently identify a Bellabel course or prove a full DLC traversal with this specific signed build.

Two further **user-controlled diagnostic runs** on the same signed app, again with separate saves and clean exit `0`, measured the original guest allocations at `main+0x1ff050` immediately after `main+0x1ff04c` summed MatBlock (`x20`) and DisplayList (`x28`). The allocator bookkeeping total is `x20 + x28 + 4`:

| Model (correlated with BFRES file-open timestamp) | MatBlock | DisplayList | Actual scratch | Original budget | Headroom |
| --- | --- | --- | --- | --- | --- |
| `NpcCommonerA` | `0x3000` | `0x1e80` | **`0x4e84`** | `0x5000` | **380 bytes** |
| `PlayerPeachElpWM` | `0x3000` | `0x0f90` | **`0x3f94`** | `0x4000` | **108 bytes** |

The first model's register sum `x8=0x4e80` recurred during the separately loaded `NpcCommonerA` in Continue. These are guest register measurements temporally associated with model loads, not model-name-tagged probe events or native Switch hardware NVN measurements. Previous failing totals were `0x5424` and `0x400c`; the upstream fix reduces them by **1,440** and **120 bytes**, respectively. The complete evidence was [posted to issue #1580](https://github.com/seedds/nxnative/issues/1580#issuecomment-6781469395) after user approval. No original saves, game resources, shader libraries or older signed apps were changed for this retest.

### Reproduce and validate

For repeat gameplay, use the **November 10 upstream-NVN signed app**, not the older four-byte-ticket preview, with separate isolated New Game and cloned Continue saves. Verify original-RESTBL New Game, Peach in a course, a full course clear, Bellabel Park, audible SDK21 movie/audio, controller movement and felt DualSense rumble. The signed app has full shaders and the indexed original Program0 RomFS sidecar. Any future observation must name the actual app/source and distinguish what the user saw from what a log proves; gameplay must **not** be automated or controlled by tests. The original game files, normal saves, shader assets and preserved older signed apps stay unchanged. Run synthetic CPU NVN/capture tests independently of gameplay.

## Open

The BFRES underallocation is resolved in upstream main by **`f02d0474`**; [#1609](https://github.com/seedds/nxnative/pull/1609) is closed and **must not** be rebased, merged or enabled in this profile. [#1580](https://github.com/seedds/nxnative/issues/1580) remains open for maintainer review of the posted measured retest. The local diagnostic +16 KiB RESTBL overlay must **never** be upstreamed as a game-data patch. This profile is ready for upstream review, but bringing the Edition to a clean main-derived build still requires original-author [#1253](https://github.com/seedds/nxnative/pull/1253) or equivalent update-only Program 1 support, SDK21 [#1561](https://github.com/seedds/nxnative/pull/1561), Control [#1562](https://github.com/seedds/nxnative/pull/1562), Mac identity [#1586](https://github.com/seedds/nxnative/pull/1586), and the general **indexed Program0 RomFS** contribution from [#1639](https://github.com/seedds/nxnative/pull/1639) or its author-credited safe adaptation, without #1639's obsolete title-specific heap allowance. The extracted update-only Edition lacks a separate Program0 RomFS and must use an explicitly provided, original-title-checked source, not substitute Program1 content. Recheck current-head CI and post-merge clean-build behavior as those dependencies land. Optional [#1564](https://github.com/seedds/nxnative/pull/1564), [#1565](https://github.com/seedds/nxnative/pull/1565) and test-only [#1606](https://github.com/seedds/nxnative/pull/1606) were closed after the user approved their cleanup; none is a current Edition merge prerequisite.

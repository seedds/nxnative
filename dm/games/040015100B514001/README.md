# Super Mario Bros. Wonder – Nintendo Switch 2 Edition + Meetup in Bellabel Park

Nintendo Switch 2 Edition, **Program 1** (`040015100B514001`) of the Switch 1 application `010015100B514000`, **v327680**, display version **1.2.1**, SDK **21 (Ounce)**, **NVN2**, Nintendo EPD (sead / agl / gsys). The Bellabel Park add-on content uses DLC `010015100B515001`, update **v131072**. This is a *different* executable and shader set from the original Switch 1 [Wonder](../010015100B514000/README.md); the existing Switch 1 profile and its builds must not be changed.

## What the profile needs

- The Edition executable's Program 1 has `main=ec47e6f8846d2a7b6892e2682845c725`, `subsdk0=3fddebac0ad5c3f9e018dcadca9e55ed` and `sdk=31945f745022d0232d2562252641b3d3`. `modules main subsdk0 sdk` follows its own imports. This profile registers **only** that build. Other Edition builds need a fresh binary survey and new shader facts.
- `mem_reserve 0x278000000`, `mem_alias 0x118000000`, `mem_stack 0x10000000`, `app_pool 0x240000000`, and `sys_resource 0x1000000` reflect the Edition's large memory layout. Its SDK requested a roughly 4.94 GiB heap, and the NPDM declares a 16 MiB system resource. Do not reuse Switch 1's memory partition.
- `render_cond on` is **required**. The Edition uses NVN conditional rendering to suppress a second shadow-mask clear. Without it, the host performs the later zero clear even when the predicate forbids it: the R8 mask subsequently downscales black instead of white, making the fountain and ground incorrectly dark. A/B GPU pass captures found the earliest mismatch in the first shadow-mask producers, and the profile's conditional-render setting restored the Switch 1 reference coloring.
- The current upstream BAHS parser fix (`04df08d4`) excludes three false program entries previously inferred from the `agl` control-section words. The resplit of the same v327680 game files removes these three phantom keys, renumbers subsequent stage indices and preserves both vertex/pixel pair tables; it is **not** a change of game dump.
- `shader_versions v327680`, the 30,630-entry Program 1 shader map, `pso_pairs.tsv` and the game's own shader facts are separate from the Switch 1 title. The build must translate them for the **current** `DMSH_CHAIN`; older experimental Mac shader libraries cannot be reused after a chain update.

## Input and dependencies

The source is an **extracted** update-only folder, `updates/327680/program/0/{exefs,...}` and `updates/327680/program/1/{exefs,romfs,control}`, with Program 1 selected; the new Bellabel DLC lives under `dlc/010015100b515001/0/updates/131072/program/0/romfs`. The original official Edition title and 384-pixel icon are in `program/1/control/Acd_1/`. Do not commit those game files, any decrypted executable, shaders or extracted resources to nxnative.

- **Prerequisite:** upstream [PR #1253](https://github.com/seedds/nxnative/pull/1253), or its equivalent, makes the dump packer understand `program/<n>` and an update-only Edition layout. At the time of testing, #1253 had merge conflicts and one failing lint check; until that work lands, an unmodified upstream builder cannot pack this folder.
- **Prerequisite:** [PR #1586](https://github.com/seedds/nxnative/pull/1586) preserves the selected Edition Program 1's **own Mac save/cache identity** `040015100B514001`, distinct from the original application ID `010015100B514000`. The first clean build pointed its `DMTitleID` and default bundle ID at the original Wonder saves despite selecting the Edition profile. The independent, general packer fix is now upstream for review (40 focused tests passed); it complements pending #1253 without duplicating that PR. Original Switch 1 saves must remain separate.
- SDK 21's movie output calls `GetVirtualOutputDeviceProperties` and an `OpenOutputStream` overload without flags. Separate [PR #1561](https://github.com/seedds/nxnative/pull/1561) supplies the missing general host hooks required for the opening movie.
- [PR #1562](https://github.com/seedds/nxnative/pull/1562) imports the Nintendo Control NCA and `Acd_1` Edition title/icon automatically once Program 1's folder is selected, rather than relying on manual labeling or the Switch 1 icon.
- **BFRES prerequisite:** [issue #1580](https://github.com/seedds/nxnative/issues/1580) diagnoses the original-RESTBL BFRES model scratch overflow. Independent generic draft [#1609](https://github.com/seedds/nxnative/pull/1609) implements actual **four-byte guest command tickets** for eligible solitary indexed draws, writes their real 48-byte canonical draw/END to guest-provided **control memory**, and charges both GetUsed counters truthfully. The measured original-RESTBL requests for `NpcCommonerA` and `PlayerPeachElpWM` now fit. This is a required prerequisite of the Edition's `nvn_draw_ctl on` profile, not a title-specific heap patch or a claim of whole-game validation. [#1565](https://github.com/seedds/nxnative/pull/1565) remains optional record compaction; [#1564](https://github.com/seedds/nxnative/pull/1564) remains optional RomFS overlay tooling, **not** the BFRES correction.
- **Complementary indexed Program0 RomFS:** SDK 19+ `MountRom(name,index)` requires distinct per-program storage. Contributor [#1639](https://github.com/seedds/nxnative/pull/1639) includes related general support, but its game-specific +16 KiB heap workaround is **excluded**. The [BrentRosen-credited fork-only candidate at `b93706e1`](https://github.com/ishtiaq156/nxnative/tree/integration/program1-indexed-romfs-w10-20261107) implements read-only indexed mounts and explicitly supplied Mac Program0 directory/image sidecars. It fails closed before packing if the original source overlaps the output app, its temporary/swap/cache paths, or an output is nested inside a signed source app or directory. The additional source-alias correction rejects a symlinked staging `.app.partial` or a symlinked/hardlinked `.key.partial` that could mutate an external original image. A **leaf symlink inside the replaced output `.app` pointing to an independent external original image is valid**: the packer resolves and copies the external image before swapping the output; the temporary link itself disappears with the old app, so a stable external source path is preferable for repeat builds. The canonical update-only Edition dump has Program0 NPDM and selected Program1 RomFS **but no separate Program0 RomFS** by design; missing original content fails closed, never silently mapped to Program1 for index0. iOS indexed-sidecar packaging is not implemented.
- **Explicit original-image and integration evidence:** The original-title-checked, complete `DMROMFS1` image from an existing signed original Wonder 1.2.1 Mac app passed **read-only source/index preflight** and can be provided explicitly as `romfs_programs/0.img`; this does **not** establish native hardware content/version parity. The earlier [fork-only combined source `1fc48cdb`](https://github.com/ishtiaq156/nxnative/tree/integration/wonder-final-headless-20261107) passed **399/399 headless checks** and an arm64 host-only build, both numeric exit0. The [current fork-only source head `003626c1`](https://github.com/ishtiaq156/nxnative/tree/integration/wonder-required-ci-hygiene-20261107) also integrates independent #1675/#1682 CI repairs and #1609's test-switch registry correction; **114/114 Mac/NSP/NUP and 11/11 documentation checks**, environment scanner and diff/syntax validation passed on that exact head. The earlier arm64 host-only build passed and its C/ObjC source is unchanged in the current branch. This is source/packaging evidence, **not** full Bellabel gameplay or a newly signed preview. Current source shader chain `3ee52af3ca18` differs from preserved signed preview `844bf1a5ea8f`; the existing 30,630-shader library and Metal pipeline archive cannot safely be reused without ABI-matched regeneration.
- Offline Mac packaging and the resource-size-table issue below are distinct from recognizing the game: signing or successful packing does not establish a fresh save boot.

## Mac bring-up and what was checked

On a **Mac mini M6, macOS 27.0.1**, an earlier *isolated* experimental Edition port (`671c68e1` plus local host/packer modifications, shader chain `adec7d81d970`) displayed the title, reached in-game scenes and passed gameplay tests across several Wonder courses and Bellabel Park; controller and rumble worked. A subsequent metadata-only patch replaced its provisional window title/icon with the official Edition Control data. **These are historical tests of that older experimental host, not tests of this upstream PR branch.**

A fresh new-game save on the *older experimental host* initially crashed while creating several BFRES models: its guest allocator returned a null pool after a model scratch allocation. A local **diagnostic-only** override raised 1,243 non-animation geometry-model sizes by 16 KiB in a runtime resource-size table, without changing the original ROM. Together with host audio hooks and bounded command-memory experiments, this got through Course900 and the online-selection movie and rendered at least 4,200 frames. **That historical override is not the fix and is absent from this profile.** The later per-model allocator analysis traced the real discrepancy to host NVN command-record bytes, corrected for the measured cases in generic draft #1609 with four-byte command/control tickets and no RESTBL modification.

A **new clean Mac app** was then built from the PR integration (`710d03e5`, shader chain `844bf1a5ea8f`) with all 30,630 verified shaders, official Edition Control metadata and a GPU-specific offline pipeline archive. Its first two manual launches reached the save menu, then crashed after choosing **Continue**: `[RED] BufferInitialize: pool has no storage`, followed by `h_nvnMemoryPoolGetFlags(NULL)` and host exit 139. That older app later passed courses/Bellabel **with the isolated +16 KiB diagnostic overlay**; this cannot validate original-RESTBL allocation.

A **separately signed 1.2.1 four-byte-fix preview** (host `070a30457362`, original RESTBL, no overlay) subsequently reached New Game character confirmation and the previously failing Peach model in a real course. For real World 1 frame **2350**, its NVN capture contained **33 canonical ticket expansions**; **2/2 independent replays exactly matched the presented 3840×2160 image digest**, while **69 of 334,308 post-frame memory blocks differed**. This demonstrates the measured BFRES correction and one presented-frame replay, **not** full memory-state equivalence, a complete original-RESTBL course clear, Bellabel Park or sustained multi-queue GPU safety. Latest #1609 adds source tests and a *defensive* 32-byte fallback regression; that 32-byte grant is **below the NVN/NVN2 advertised 512-byte minimum** and must not be claimed as hardware-valid. The original signed app and this separate preview are both preserved; neither was rebuilt for documentation changes.

### Reproduce and validate

For manual gameplay, use the existing signed four-byte-preview launcher with an **isolated cloned Continue save**, then its separate `newgame` argument for a fresh save. Check original-RESTBL New Game beyond character confirmation, a full course clear, Bellabel Park, audible music/effects and SDK21 movie playback, controller movement and felt DualSense rumble. Request a screenshot only for a meaningful milestone, visual defect or crash; gameplay must **not** be automated or controlled by tests. The original game files, normal saves, shader assets and the two signed apps stay unchanged. Run synthetic CPU NVN/capture tests independently of gameplay.

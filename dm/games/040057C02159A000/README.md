# Nintendo Switch 2 Welcome Tour (`040057C02159A000`)

Update v262144, main build `6e3d11763a988c6b947510e0ae08ad00`, SDK 20.5.29 (Ounce), NintendoWare Bezel Engine 2.16.0, NVN2. The NUP has no NACP or icon; its display version is unknown. Pack it with `--app-name "Nintendo Switch 2 Welcome Tour"`.

## Status

Mac bring-up on 2026-11-16: the H.264 opening cinematic, character selection and confirmation, the venue introduction, the information-desk dialogue in Area A (Joy-Con 2 (L)), and left-stick movement after the introduction. Input advances text and selects the character. The venue runs at about 60 fps on a 16 GB M6 Mac mini; the original frame-2100 interval measured 16.67 ms median frame time and 8.77 ms median GPU time. First-use pipeline compilation causes hitches. The initial six test boots totalled just under ten minutes. Two later debug runs retested chain `ae3a3f6c6f22` through the same introduction and movement; with current generated tables its frame-2100 interval measured 16.66 ms median frame time and 8.52 ms median GPU time. This is verification, not evidence of a speedup.

The shared AS and RT backend now passes the previously aborting Balloon Hunt entry path. Exhibits, a real Joy-Con 2's mouse and rumble, later areas and iPhone gameplay are not validated by this bring-up. Existing host mouse support was tested on this title separately (see [Found on this game](#found-on-this-game)); it is not new evidence from this run.

## What it needs

- [`game.tsv`](game.tsv) registers the update's module builds. Load `main`, `subsdk0`, `subsdk1` (NintendoSDK_movie), `subsdk3` and `sdk`, in that order. `subsdk2` supplies C library imports answered by the host. `subsdk4` contains NVIDIA's RTCore CPU linker. The offline Metal RT library supplies that backend path, so this module is not loaded. The RomFS's NRR registers 36 NROs, rewritten and loaded through the existing `nn::ro` path.
- The NPDM declares 16 MB of system resource. At startup the game reserves 2 GB at alias +0.06 GB (returning to `main+0xaae404`) and 56 GB at +2.06 GB (`main+0x721a04`). The profile preserves the console's 64 GB alias region and 9 GB application pool. It does not claim an iPhone-sized layout. The provisional profile's heap check reduced the pool to 1 GB, but had stopped before the full application loaded; that guess is not retained.
- `depth_mode zero`: the game calls `nvnDeviceSetDepthMode` with near = 0. Runtime vertex selection follows that state, and offline pipelines use the matching entries.
- No game-specific `patches.py`, host build gates or rewriter cuts. The shared SDK matcher shrinks the address-region node area to 62 MB.

## Rendering and memory

154 Bezel `.bea` archives use the existing SCNE/zstd archive reader. RomFS also holds 423 WebM movies, 94 BFSTM streams, an MP4 opening movie and the NROs. Chain `0eaf28e580b0` builds all 6,766 ordinary shaders and one universal library containing the 12 RT modules for Mac and iOS, with no undecoded bindings, unfillable driver-bank reads or reported translation losses. The final UMOV relocation fix changes only `rt_library_b.metal` among all 6,839 stored Mac sources; the ordinary sources are byte-identical to the preceding `535e798516ad` build. The shared goto-condition fix earlier changed ordinary control flow too, as covered by the regressions below.

**Resolved:** hull shader `0b9e5d475e9afd21` uses an indexed Ampere patch-output store for its tessellation factors. The translator now implements that instruction's patch-map addressing, including user outputs and vector stores. `DeviceRegisterFastClearStencil` registers a compression hint; the host accepts it because Metal manages compression. Both fixes are general, with no game/build gates (see [Found on this game](#found-on-this-game)).

**Resolved, expected unused binding:** `8102f306f50c533c` reports vertex uniform slot 7 without a bound buffer near frame 7. It comes from `flow~flow103.ounce.bea`, `_flow/flow103.bnbshpk`, BNSH +0xb000, variant 0 (`vs_archive.bin` index 236). The affected depth/stencil triangle pairs it with `cf6829bda495959d`. Targeted draw dumps at frames 6–9 show slot 6 +0x30 = 0 with no pending writes; that selector chooses the unskinned path. All slot-7 reads lie in the one-, two-, three- or four-bone paths. An offline GPU probe of the translated vertex function with these captured uniforms counts zero slot-7 loads; changing that bank from 1 to 999 leaves the position bit-identical. Positive controls with selectors 1–4 count 12, 24, 36 and 48 loads. Both `main0` and the selected depth-zero `main0_z` pass. No binding or shader override is needed, and the general diagnostic is retained. The full-frame recorder refuses this game's logical sync waits (format 1); `capture8.log` and `uniform_probe/result_z.log` in the work folder record the successful targeted alternative.

**Resolved, GPU timestamp units:** Bezel's GPU profiler reads each counter report's timestamp through `nn::gfx`'s NVN2 backend (ApiVersion 200), which takes the raw value as nanoseconds (`main+0x613610` returns it unchanged; `main+0x5e3120` then calls `nn::os::ConvertToTick`). The host wrote reports in the original Switch's 614.4 MHz ticks, so a 2026-11-17 probe of the [GPU scheduling query](../../../docs/reference/services.md#application-gpu-scheduling-time) read every region at 0.6144 of the guest clock (begin and end near 607,246 s against 988,357 s) and frames 9–10 ms apart at 60 fps: the per-pass and frame GPU times feeding dynamic resolution read about 39% low. NVN2 reports now record nanoseconds ([NVN2 timestamps are nanoseconds](../../../docs/reference/frame-rate.md#nvn2-timestamps-are-nanoseconds)). On the same route on the Mac (60 fps, 200 s) the frame regions lie 16.7–18 ms apart, 12–50 ms behind the guest clock, and the frame's GPU time reads 7.47 ms against the host's GPU p50 of 7.53 ms.

With the provisional 1 GB pool, resident memory settled around 5.5 GB in the information-desk scene, rather than growing between repeated samples. The final 9 GB pool run reached 6,966 MiB resident at frame 1800 and fell to 6,814 MiB (about 6.7 GiB) at frame 2100 (7,231 MiB of Metal allocations at that point); resident and Metal allocations overlap and must not be added. Longer coverage of the final pool's memory remains open. A virtual mapping count exceeding the application pool is not a resident-memory measurement.

## Ray tracing (open)

**Current:** the allocation, RT-program initialization and continuation failures on the Balloon Hunt entry route are resolved. The same isolated-save route now executes a real `512×288×1` ray dispatch against 32 instances and reaches the “Single Balloons” title and instructions. `rt0eaf_balloon.log` continues through frame 10,500 with no RT shader fault or GPU command error, then exits cleanly on SIGTERM. Screenshots at frames 3,800 and 4,200 record the title/instructions. This does not establish completed mouse gameplay, the exhibit's final 3D picture, or Stunt Driving coverage; a real Joy-Con 2 was not attached. The final sampled resident footprint was about 8,104 MiB on the 16 GB M6.

The resident graphics archive contains `multi_bounce_opaque` and `visibility_buffer_opaque`, each as a combined BNSH and separate raygen/closest/miss files: 12 content-keyed modules, with 70,400 original code bytes including padding. The RT descriptor occupies BNSH program +0x38 and control stage 8. The splitter now extracts it independently of the graphics/task/mesh descriptors and keeps the complete control metadata. No game shader code or material flags are patched.

A format-aware census of all 2,195 material records finds 25 with enabled RT options, exclusively in **Balloon Hunt** (`tgame~tgm309.ounce.bea`, Area I / `FieldID_12`) and **Stunt Driving** (`tgame~tgm313.ounce.bea`, Area K / `FieldID_13`). Twelve enable reflection reads and draws; thirteen enable draws only; 1,811 have both options off and 359 have neither option. Scene setup creates those models: `nro31` loads `tgm309_bg00` and its pillars, including enabled material `tgm309_t201m1`; `nro32` loads `tgm313_car00`, whose body/window materials enable both. Area A alone therefore did not cover the missing RT path.

**Resolved allocation abort:** the unimplemented void AS-size query left an output at stack +0x30 containing the previous position-buffer GPU address, `0x800d333100`. Bezel requested 549,977,272,576 bytes (about 512.2 GiB), allocation failed and `main+0x5e8120` aborted. Actual Metal requirements replace that untouched output; the first observed sizes were 1,344, 30,464 and 229,184 bytes. See [AS sizing and storage](../../../docs/reference/nvn-objects.md#acceleration-structure-sizing-leaves-a-buffer-address-in-the-size-output).

**Resolved missing program:** the old raster-only builder returned an empty RT program, then queue snapshotting stopped with `cannot retain a program without an initialization serial`. The [shared RT implementation](../../../docs/reference/nvn-objects.md#nvn2-ray-modules-have-no-initialized-program) supplies the metadata-driven library, actual catalog/program ownership, opaque handles, RT resources and Metal traversal. The shipped RTCore can deserialize/query/serialize these inputs, but its NVIDIA backend cannot create a Metal pipeline; loading it is not the fix.

**Resolved uniform continuation relocation:** the first integrated run reached ray dispatch, then fault 5 reported continuation 3. Logical-ID substitution handled GPR `MOV` but missed uniform `UMOV` (opcode 0x882). Both visibility variants use that instruction on a fallback path, followed by `+3`; leaving its immediate zero selected 3 instead of the planned continuation (9 or 14 in that library). Both emitters now share the same validated relocation source while retaining their register classes. A synthetic regression fails before the fix and passes 49 checks afterward; the actual failing route then passes without weakening stage, ownership or bounds checks.

Independent whole-host fixtures use the original modules, real public builders/handles, queued geometry and SBT writes, Metal AS builds, recorded ray dispatch and NVN texture readback. In each actual encoder mode, 1,872 checks pass, including exact whole integer images for hits, misses and mixed rays, the full compute push snapshot, resource-scope isolation and explicit invalid-use faults. Earlier numeric bounce/visibility oracles check native ray, payload and frame behavior separately; they do not replace gameplay coverage.

**Limits:** the shared backend's supported ABI subset is documented in the reference link. Stunt Driving, full mouse-controlled Balloon Hunt play and iPhone RT remain untested. First creation of the universal RT pipeline took about 110 seconds in the earlier isolated M6 fixture, versus about 11–17 ms with its cache warm; this is a load-time limitation, not an FPS measurement. A smaller optimized artifact did not demonstrate a reliable cold-load improvement, so the production optimization default is unchanged.

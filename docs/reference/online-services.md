# Optional online-service backend

This backend is independent of a game library or authorization interface. I extracted the engine changes from my originating fork for the [scope discussion](https://github.com/seedds/nxnative/issues/951). Default builds remain offline. No game, firmware, service certificate, account document, password, OAuth token or observed leaf certificate is distributed here.

### Native client TLS

- **Symptom:** an enabled native socket connects, but the SDK's TLS context is still an unavailable-service cut.
- **Cause:** a raw TCP transport does not implement the SSL service, its object ABI, certificate verification or asynchronous socket ownership.
- **Fix:** `hle_ssl.c` adapts the C/C++ service entry points to `hle_ssl_apple.m`. Opaque guest objects key bounded owned registries. The backend duplicates a guest descriptor with its generation, preserving the underlying connection through guest close/reuse; destroy/finalize invalidate the owned objects. Blocking methods use the guest-aware HLE wait path. The implementation handles real handshake/read/write/poll, nonblocking progress, server-certificate buffers, client PKCS#12 data and ALPN. Unsupported operations fail rather than claiming a session. Contexts accept normal system PKI and explicitly imported server anchors, always retaining hostname verification.
- **Private PKI:** a configured peer may supply a private anchor, scoped to that peer/connection. `hle_nextendo_x509.c` uses strict X.509 purpose, SAN, chain, current-time and strength checks without default trust paths or a verification bypass. Optional explicit leaf enrollment accepts only identical DER for one enrolled logical identity, with self-signature, validity, server purpose and key/signature strength checks. It neither adopts an observed certificate automatically nor changes system trust. A numeric NEX handoff is allowed only by an explicit alias paired to the same exact identity, address and enrolled certificate.
- **Build:** `dm/tools/apple_crypto.py` pins OpenSSL source by SHA-256 and builds static libcrypto for the selected Apple SDK. The DM_OPENSSL_ROOT build variable may point to an already prepared target-compatible prefix. The iOS source/flags generator propagates the static archive to both real and smoke links; a Mac archive is not an iPhone dependency. The [OpenSSL license and provenance](../../dm/third_party/notices/OpenSSL/PROVENANCE.md) must accompany redistributed linked applications. No OpenSSL binary is committed.
- **Check:** I exercised real loopback TLS through the guest's registered C/C++ gates using ephemeral test certificates: SNI/hostname failures, nonblocking progression, data, polling, certificate buffers, descriptor generation/close ownership, context IDs, ALPN and lifecycle. The private verifier separately rejects malformed DER, wrong purposes/names/anchors, weak/invalid signatures, expired/future leaves and an unpaired/rotated enrolled certificate. No user account or public game server is involved in these fixtures.

### Explicit routing and NSD

- **Symptom:** a service template reaches native DNS unchanged, or an IP handoff loses the logical TLS service identity.
- **Cause:** Horizon NSD expansion, host DNS and TLS identity policy are different layers. Redirecting DNS alone cannot provide either NSD semantics or trustworthy SNI.
- **Fix:** `hle_nsd_backend.c` expands a bounded retail Fqdn template and documented account aliases before the socket resolver consults a startup DNS provider. `hle_nextendo_routes.c` publishes a bounded immutable policy only after validating the complete configuration and its certificate hashes. It registers separate DNS admission, TLS admission, scoped-CA and enrolled-leaf callbacks. Failed loading publishes no partial table. Explicit retry can recover an unconfigured process; it cannot replace an already published policy.
- **Opt-in:** `DM_NETWORK=nextendo` enables the service boundary explicitly, including fail-closed behavior without a usable policy. `DM_NETWORK=auto` enables Nextendo only when `DM_NEXTENDO_ROUTES` is nonempty; without a profile it retains ordinary local DNS and local sockets. An explicitly supplied invalid path still fails closed rather than silently becoming unrestricted. LAN/LDN modes do not enable the online account or service policy. The optional `dm_bcat_online_enabled()` capability additionally requires a fully published nonempty profile; it performs no account or network request.
- **Private configuration:** `DM_NEXTENDO_ROUTES` names an absolute local TSV. A directory, table and referenced DER file must not be symlinks or group/world-writable; owners, regular-file types, lengths and SHA-256 are checked. V1 starts with `NXNEXTENDO_ROUTES_1` and has five tab-separated fields: logical host, IPv4 address, TLS verification name (or `-`), DER filename (or `-`), SHA-256 (or `-`). V2 starts with `NXNEXTENDO_ROUTES_2` and prepends `exact`, `suffix`, `label`, `pinned-exact` or `pinned-address`. `@host` preserves the matched logical name for TLS. Longest exact/label/suffix precedence is deterministic. Leaf enrollment is exact-only; numeric aliases cannot authorize a new identity or certificate. Supply provider endpoint facts and trust separately; no enrollment is downloaded here.
- **Composition:** a cancellable `GetHostByNameCancel` adapter must use the same `net_resolver_name` admission before its numeric fast path or native DNS job. Otherwise that ABI could bypass the policy enforced by `GetAddrInfo`. The separate cancellation contribution and this provider contribution must retain that shared boundary when stacked.
- **Check:** the route fixtures exercise complete/invalid/partial tables, ownership/permissions, hashes, DNS/NSD normalization, ABI pointer layouts, canonical logical names, precedence, immutable publication, explicit recovery and actual loopback TLS with scoped CA/enrolled-leaf/numeric handoff. `t_online_policy` proves that unconfigured AUTO keeps local DNS, configured AUTO consults the provider, explicit Nextendo fails closed and negative admission preserves the previous guest errno.

### Account and social providers

- **Symptom:** a service transport works but the SDK has no usable account identity/token or friends snapshot.
- **Cause:** a saved OAuth social token is not a NEX game credential, and a desktop authorization workflow is not part of the service ABI.
- **Fix:** an embedding host registers `dm_nextendo_set_credential_provider` before guest startup. The callback copies a bounded schema-1 document from its already authorized private storage; it must not open UI or wait for user authorization. There is no implicit Keychain/document reader, command-line credential, child preflight process or browser flow. Without a provider, availability is false and credential operations fail normally. Disabled modes never call the provider. The local user/24-byte host UserHandle contract remains unchanged; online hooks check both the issued handle and actual local UID.
- **Credential contract:** the document contains `schema_version: 1`, `token_kind: "nex"`, the provider's original `nx2` proof, an `identity` object (`pid` and `username`), numeric `created_at`/`expires_at`, and a bounded string `scopes` array. Local checks enforce canonical proof encoding/shape, matching identity and coherent unexpired times. The host cannot verify the provider's private HMAC; the service authenticates that original proof. A syntactically coherent local record is not evidence of server login. OAuth-only, missing, malformed, incoherent and expired records are rejected. Never publish this document or put it in an environment variable.
- **Game token:** `dm_nextendo_set_game_version` supplies the actual installed version; otherwise the bundle's version is read. The existing ID-token envelope carries the unchanged NEX proof and version, with a process-local RSA signature. The `nx-port-studio` issuer is retained as the original provider client-envelope label, not a claim of Nintendo authentication or a new credential. This local signature is not substituted for the NEX proof and is not advertised as a provider-registered public key. A real game update remains mandatory where the provider requires it.
- **Lifecycle:** account/friend async contexts use owned state, real operation results, generation-checked cancellation, move/swap/destruction and lifetime-bound system events. Guest event construction remains on the callback-capable HLE path; blocking service methods use WAIT gates. Pending/destroyed contexts do not publish successful results or signal reused event bindings.
- **Social data:** the bounded native HTTPS boundary admits only the canonical provider's `me`, `friends` and `presence` resources. It disables cookies, credential storage and redirects and retains normal system TLS. Snapshots validate schema, bounds and identity, expire on their monotonic cache deadline and remain owned by each caller. Friend/Presence object writes are admitted only after verifying SDK constructor/getter semantics; unknown layouts fail instead of guessing. Invitations and unsupported profile operations remain unavailable. A user-facing authorization/settings interface belongs in an embedding application.
- **Check:** I used synthetic unauthenticatable NEX-shaped records and an injected HTTP transport to verify negative credential cases, correct output bounds/identity, local signatures, provider absence, disabled modes, real async result/event/cancel/reuse semantics, friend layouts and malformed/identity-changing social responses. These fixtures do not establish real server authentication or a playable online match.

## Validation and limits

From an Apple-silicon checkout, with a target-compatible static crypto prefix:

```sh
make -C dm/host/tests GAME=010015100B514000 ssl ssl-sanitize
make -C dm/host/tests GAME=010015100B514000 nsd nsd-sanitize online-policy online-policy-sanitize
make -C dm/host/tests GAME=010015100B514000 nextendo-routes nextendo-routes-sanitize nextendo-x509 nextendo-x509-sanitize
make -C dm/host/tests GAME=010015100B514000 nextendo-account nextendo-account-sanitize nextendo-api nextendo-api-sanitize nextendo-social nextendo-social-sanitize
```

`DM_SSL_TRACE=1` enables at most 128 numeric state events and preserves errno; it never prints names, addresses, pointers, certificates, credentials or stream contents. `DM_SYSTEM_DATA_DIR` can point at the player's private original system resources for the certificate store; none is distributed here.

In my originating fork I validated the Mario Kart 8 Deluxe 4.0.1 online connection path on Mac (not a completed Nextendo race), a Smash 13.0.5 arena on Mac, and Splatoon 2 EUR 5.5.2 reaching its lobby and Territorial queue. Those configurations used separately reviewed service trust policies; no observed leaf is part of this contribution. I did not complete a Splatoon match. These historical tests do not qualify every game, iOS online, a new upstream shader chain or this rebased extraction. I have not repeated the five-game graphical regression on this backend-only branch; the no-GUI fixtures, HLE registry and Apple compile checks are separate evidence.

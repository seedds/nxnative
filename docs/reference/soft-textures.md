# Soft textures (the kartnative / plumber-racer-2 family, ported to this tree's anchors)

`tex_soft` (default off; `DM_NVN_TEX_SOFT`) is a packaged texture with a real layout whose texture keeps its finest level out of the host texture and out of memory: `tex_desc` builds it from level 1, every upload reads the source one level down (level shift `sk`, on the GPU and on the CPU), and the pages only level 0 holds go back to the system (`nvn_dirty_release`, `soft_sweep` after a 300-frame grace) unless a GPU copy reads or writes the texture (`soft_harden`, [below](#gpu-copies-and-a-soft-texture)). `ReadTexels` reads the storage, as for every texture uploaded from it. A texture view that starts above level 0 takes the game's level number as it is, one level coarser in the half-size host texture (the view lookup does not shift it). Soft textures upload on the CPU while their pool has no zero-copy buffer (`mtl_pool_wrapped`): iOS wires a buffer's whole memory pool, for a pool the GPU may otherwise never address. A second switch, `DM_NVN_TEX_RELEASE`, arms the release path; both off by default, so no game sees this until its profile names `tex_soft` (Mario Kart World's `game.tsv` carries that row in the community lines this port comes from, `dm/games/<id>/README.md` in each).

Data: on the iPhone Duo (iOS 27.3), a full Mario Kart World free-roam drive at 3.7–3.9 GB footprint (4,457–5,262 without; the same anchors' GPU-only uploads at 3.7→851 MB wrapped pools in the kartnative line), and the long-frame record without the file-backed page-in spikes this path had carried (p95 81 vs 215 ms). The 60-fps sustained state under driving is the same open problem this tree records elsewhere and did not change here.

| From | What |
|---|---|
| Symptom | a game whose large BC textures from its files cost whole-pool wiring and a finest level the GPU never samples enough to justify |
| Cause | the host texture of a large block-compressed texture is the game's own size, its finest mip and all, and the game's memory pool behind it wires identically |
| Fix | the soft texture, its release path and the CPU upload while unwired, above |
| Found on | [Mario Kart World](../../dm/games/0400C3F00006E000/README.md) (and the kartnative/plumber-racer-2 family of forks it ports, MIT) |

A released level is gone from the game's memory too (`DM_NVN_TEX_RELEASE=1`): once the system has taken the pages they read as zeros, and nothing puts the bytes back. So `ReadTexels` of level 0 of a released texture reads 0, and so does a game that reads that level from its own memory. Only a texture whose pool has no zero-copy buffer over it is released (`soft_sweep`; in practice a pool of 512 MB or more, which the host wraps in chunks on demand), after 300 frames in which nothing copied from it.

### GPU copies and a soft texture

- **Symptom:** with `DM_NVN_TEX_SOFT=1`, a region the game copies on the GPU into a large block-compressed texture shows at the wrong mip level, or shows until the texture's next upload and is then gone; the log has `[RED] GPU write into ser=… not written into its storage (the host texture does not hold its bytes): the next upload from there drops it`. A copy into the texture followed by a copy from it in the same command buffer reads the texture without the first copy.
- **Cause:** the host texture of a soft texture is half the size, with the game's level n + 1 at level n, and the copies took the game's level number as it was: a buffer-to-texture copy (`copy_b2t`), a texture-to-texture copy (`copy_t2t_enc`) and a copy through an uncompressed alias (`bc_alias_copy`) landed one level off. The buffer copy still reached the storage (`gsb_store_buf`), with no upload to follow it; the texture copy did not, as `gsb_store` takes only a host texture that holds the storage's bytes at the storage's size (`gsb_host_ok`). Only a texture the game copied from was made whole.
- **Fix:** a soft texture that a GPU copy writes into is made whole first, as one it reads already was: `soft_harden` runs on the destination in `copy_b2t`, `copy_t2t_enc` and `bc_alias_copy` before the copy is encoded. The texture is uploaded again with its finest level and stays whole from then on, so the copy takes the ordinary path at the level the game names and reaches the storage. The upload in `soft_harden` has no held GPU store to wait for (`gsb_held`): a soft texture's storage gets none, as every copy into it comes there first.
  - **A texture whose finest level's storage has gone back** (`DM_NVN_TEX_RELEASE=1`, `soft_sweep`) cannot be made whole, and stays soft. `soft_harden` says so once (`[RED] GPU copy from or into a soft texture whose finest level has gone back`). A copy from or into its level 0 is skipped: the host texture has no such level. A copy at another level takes the level one lower in the host texture (`tex_soft_level`), where the sizes agree; a buffer copy into it still reaches the storage, a texture copy into it does not and is lost at the texture's next upload (the red line above), and a copy through an uncompressed alias goes to the alias's own texture. Before, these copies used the game's level and sizes on the half-size texture, which Metal's validation refuses.
- **Check:** `t_soft_texture` (`dm/gfx/tests`): the half-size upload and its level shift on the GPU and on the CPU, a CPU write uploaded again the same way, which reads only the written level (the partial re-upload, `pkg_written`, asks about the byte range of the game's level, host level + 1, and the other levels are copied from the texture it replaces); a buffer copy, a texture copy and an alias copy into level 1 of a soft texture (the texture whole afterwards, the region at level 1 and not at level 2, the storage's bytes, the region still there after the next upload from the storage, no red line); a copy from a soft texture's level 0; a copy in and a copy out in one command buffer; and the released case above.
- **Found on:** `t_soft_texture`, written for the pull request that brings soft textures in; no game's log has shown the red line yet. [Mario Kart World](../../dm/games/0400C3F00006E000/README.md) is the game the switch is for.

### A soft texture uploaded on the CPU has no content

- **Symptom:** with `DM_NVN_TEX_SOFT=1`, `[RED] deswizzle failed format … target …` once, and the large block-compressed textures of a pool with no zero-copy buffer hold nothing of the game's.
- **Cause:** a soft texture is uploaded on the CPU while its pool has no zero-copy buffer (`keep_cpu` in `pkg_upload_`), and that loop sized each level's rows for the game's level l + 1 but deswizzled level l: `nvn_deswizzle` refuses rows shorter than the level's, for every level. The upload on the GPU had the shift.
- **Fix:** the CPU loop deswizzles level `l + sk`, as the GPU path encodes it.
- **Check:** `t_soft_texture` uploads a soft texture from a pool in chunks (`BIG_MIN`), which has no buffer until a lookup reaches it, and compares each host level with the game's next level.
- **Found on:** `t_soft_texture`; a 1024x512 BC1 texture with 4 levels.
